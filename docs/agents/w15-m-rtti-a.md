## Observed and inferred

Observed (from the image and the verification below):
- A `__tf<Class>` symbol is a lazily initializing getter, not a node. It tests the first word of `__ti<Class>`; when that word is zero it calls the base getter (or `__rtti_user` for a root class), then `__rtti_si` with the node, the class name string and the base node. A nonzero first word returns the node unchanged. The bad_typeid, bad_alloc and builtin type_info getters follow this pattern, as do the sprite and spell getters.
- `__ti<Class>` nodes are 8 bytes for root classes and 12 bytes for classes with a base. The two checked against the image (`__ti8VISprite`, `__ti13VISceneFilter`) are zero there.
- Two `__tf` symbols inline their base registration rather than calling the base getter: `__tf19SpellSummonSkeleton` registers `__ti5Spell` (with `__rtti_user`, when unset) before its own node.
- Each vtable slot is a zero adjustment word and a function word; the last function word is null in every table. The 22 tables are 6-slot spell tables, 4-slot exception tables, a 3-slot `_vt$19VIFlatFileDirectory`, an 18-slot projectile/spell table family, one 30-slot table (`_vt$8Skelight`) and one 75-slot table (`_vt$16VIRealmInterface`).
- The two destructors store a table address in their first word (exception destructor) or second word (builtin type_info destructor), and delete when bit 0 of the flag is set. The builtin one calls the base type_info destructor with flag 0 first.

Inferred:
- Node and table roles follow from the names and the registration call shape. The getters' class-name strings and base chains are read as observed registration arguments, not as a documented ABI.
- The table address is stored at offset 0 for the exception destructor and at offset 4 for the builtin type_info destructor, following the image.

## Verification performed

- Host contracts: each unit compiles with `c++ -std=c++17 -Wall -Wextra -Werror` and its `host_check.cpp` runs. All 43 pass. The vtable contracts call every slot and compare the observed name.
- EE compile: every unit compiles alone with the reviewed `authored_cpp` flags (`cc` with EE g++ 15.2.0). No unit has a header closure.
- Paired runs (private R5900 interpreter, original versus authored, identical snapshots, all callees hooked by name): nine getters and the two destructors, with the node's first word varied and, for the spell getter, the base node too. Every run reported 0 mismatches and no halts. The callee logs include the node, base and name contents, so the name strings were compared as observed.
- Mutation: changing the base argument of `__tf8VISprite` from `__ti10VIResource` to the node itself made the paired run report mismatches, so the comparison detects a wrong base.
- Vtable object check: each vtable object defines its `_vt$` symbol with the image size, and every nonzero slot has one relocation whose target is the image symbol at that slot. 22 of 22 pass; a zero adjustment word is required in every slot.
- Private full partial build: the private plan copy (the current shared plan plus the 43 entries below, input order appended, snapshot record added) passed `--check-plan` and then built: 6806 selected inputs, 6806 source compilations, one relocatable link, 5395 function bodies (the previous plan had 5384), 0 COMMON symbols, 1021 unresolved imports. The previous private build of the current shared plan had 915.
- `python3 -m unittest discover -s tools -p 'test_*.py'`: 214 tests, OK.
