# Actor virtual methods, destructors and type info (1/3)

Package `agents/w8-actor-virtuals-a`. Addresses and sizes are from the pinned private `SLUS_205.65` (`.text`); the compiled sizes are the reviewed EE g++ `authored_cpp` objects. Nothing here ran on the EE or as gameplay, and no compiled body is claimed to be a byte match: the original destructors were compiled by an older compiler, and the new bodies are 112 bytes (original 100), 144 (116), 92 (76 or 80), 184 (128), 296 (140) and 32 (44).

## Evidence

Every function has a `host_check.cpp` beside it (not a plan input) that failed under single-edit mutations of the offsets, flag masks, call arguments and class-name literals. Each function was also run against the image in the existing R5900 interpreter: `docs/agents/w8-actor-virtuals-a-compare.py` (registry in `w8-actor-virtuals-a-compare.json`) executes the image's function and the freshly linked authored object with the same randomized scenario, intercepts every imported call, and requires equal call logs (argument registers, class-name strings read through their pointer, the single height argument), equal object or type-info bytes, and for the type-info functions an equal return value. The last run was 1000 seeds per function with zero mismatches. It needs the private executable and toolchain through `NORRATH_EXE` and `NORRATH_EE`, and imports the interpreter from `combat-reactions-compare.py`. The data symbols the authored object imports (vtables, base type-info objects, the world pointer word) are placed at their image addresses so stored words compare directly. The mutation runs used the same harness with the edited source.

## Observed

- Thirteen destructors share one shape: store the class vtable at object+72, call the base destructor with flag 0, then `blockFree` on the object when bit 0 of the incoming flag is set. The base is GameObject for Container, Trigger, MissileTrap, Shooter, FireBomb and PushPhysicsProp, Creature for Teleporter, AutoProp for GothTrap, HateHole, HateBridge and HackDoor. HateInto and HateGate additionally destroy a `FxCreatureState` member at object+408 with flag 2, after the vtable store and before the AutoProp destructor.
- `_$_15FxCreatureState` (0x1e5db0) only deletes the object when bit 0 is set (`__builtin_delete`). `_$_14AnimationState` (0x164050) clears a back-pointer word at 1552 in the block pointed to by +0, then walks the signed byte count at +5 clearing the word at +20 of each block pointed to by the 32-byte slots from +12, and deletes on bit 0. `_$_9WorldPart` (0x21bdb0) calls `worldSetDoorHeight` and `worldReleaseDoor` with the signed halfword at +76 (and the halfword at +78 as a float) before the GameObject destructor.
- Fourteen type-info functions (`__tf` of Container, Trigger, MissileTrap, Shooter, FireBomb, PushPhysicsProp, Teleporter, NPC, HateInto, HateGate, GothTrap, HateHole, HateBridge, HackDoor) test the first word of their 12-byte object; zero runs the base's type-info function and `__rtti_si(this, name, base)`. Bases: GameObject, Creature (Teleporter, NPC) or AutoProp.
- Addresses: dtors `_$_9Container` 0x30dfb0, `_$_7Trigger` 0x30e4e8, `_$_11MissileTrap` 0x3107d8, `_$_7Shooter` 0x310890, `_$_8FireBomb` 0x312100, `_$_10Teleporter` 0x3127c8, `_$_15PushPhysicsProp` 0x312b70, `_$_8HateInto` 0x315390, `_$_8HateGate` 0x315458, `_$_8GothTrap` 0x315520, `_$_8HateHole` 0x3155d8, `_$_10HateBridge` 0x315690, `_$_8HackDoor` 0x315748. Type info: `__tf9Container` 0x30e018, `__tf7Trigger` 0x30e550, `__tf3NPC` 0x30fb50, `__tf11MissileTrap` 0x310840, `__tf7Shooter` 0x3108f8, `__tf8FireBomb` 0x312168, `__tf10Teleporter` 0x312830, `__tf15PushPhysicsProp` 0x312bd8, `__tf8HateInto` 0x315408, `__tf8HateGate` 0x3154d0, `__tf8GothTrap` 0x315588, `__tf8HateHole` 0x315640, `__tf10HateBridge` 0x3156f8, `__tf8HackDoor` 0x3157b0.

## Inferred

- The names `__ti<Class>` for the 12-byte objects follow the existing `vslots-a` type-info units; the image has them as COMMON, so under `-G0` they land in BSS here.
- The two `__builtin_delete` and `blockFree` choices follow the observed callee for each class.

## Imports opened (3)

- `_$_8AutoProp` (0x224c70): the base destructor called by five AutoProp-derived destructors. Declared with that exact name.
- `__ti8AutoProp` (0x8eb518 in the image): the base type-info object used by six type-info functions. Nobody defines it yet; whoever authors `__tf8AutoProp` (still unresolved on the base) should define it as a 12-byte object.
- `worldReleaseDoor__FP12_worldHeaderi` (0x17d318): called by `_$_9WorldPart`; the return value is ignored.

Already-unresolved names these units also call (not new): `__rtti_si`, `__tf8AutoProp`, `__builtin_delete`, `worldSetDoorHeight__FP12_worldHeaderif`. `__rtti_si` is the original name, as in the `vslots-a` type-info units; the `light-methods` units import it as `norrath_rtti_si` instead, so the two names are both unresolved and need one provider (or a reviewed alias) from whoever authors the function.

## Authored but never executed

All of it on real hardware or in the game. Every function ran only on the host (mutation-checked contracts) and inside the comparison interpreter. In the comparison the callees are stubs that only log, so nothing downstream of `blockFree`, `__builtin_delete`, the base destructors, `__rtti_si` or the world door calls is exercised. Pointer words are 32-bit on the target; host checks use a base offset where a pointer is dereferenced.
