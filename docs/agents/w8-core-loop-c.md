# Core game loop, engine and scene switching (3/5)

Package work is on `agents/w8-core-loop-c`. Addresses are from the pinned private `SLUS_205.65` image (symbol table plus the instruction bytes, read locally; nothing from it is committed). New source is under `experimental/sources/w8-core-loop-c-*`, one function or data object per directory and per commit. Each directory holds the source and a `host_check.cpp` (a host contract, not an EE plan input; it defines `NORRATH_HOST_CONTRACT` where the source has a hardware seam). Each source opens with its own observed / inferred / unknown comment.

## What was done

Eleven functions and twenty data objects, each compiled with the reviewed EE `g++` under the unchanged `authored_cpp` flags, each with a host contract that passes, each its own commit pushed to `agents/w8-core-loop-c`.

Functions (original size in bytes): `engineSetBlur__Fi` (28), `engineGetAIStepCount__Fv` (84), `gameItemTreasureRamp__Fv` (60), `gameGetFullLevelName__FPc` (76), `gameDeathStart__Fi` (64), `gameLineClear__Fv` (100), `gameLineDebugDraw__Fv` (8), `engineLoadEnvTex__FP8_texture` (92), `engineReboot__Fv` (132), `frameNumWrapped__Fv` (116, a local symbol), `gameCheckNoSaveZone__Fv` (160).

Data: `engineDisable30fps`, `engineFullFrameMode`, `engineLastAITime`, `engineScissory1`, `engineScissory2` (file value 447), `engineScreenSlide`, `engineYOffset`, `fadeIconY` and `fadeTimer` (112 bytes each), `firstTime` (the BSS byte at 0x00486d88), `flaredIn`, `flaredOut`, `gameAutoMapMode`, `gameCameraShake` (float), `gameCreatureThinkSpinner` (byte), `gameDeathTimer` (halfword, file value 0xffff), `gameDeathTimerSingle` (four halfwords), `gameLevelLoading`, `endTimer` (0x00484bec, file value 1) and `endTimer.1059` (0x004842e8, bound with an assembler label, as `pause_menu.cpp` already imports it).

## Observed

- The compiled bodies are not claimed to match the original bytes. Under `-G0` the compiler does not use gp-relative addressing, so sizes differ, and float literals go to compiler-generated constants. Control flow, call order, arguments and data reads and writes were read from the instructions.
- `engineGetAIStepCount__Fv`: limits either `lastFrameVBlankCount` (when `trippleBufferMode` is zero) or the signed byte `nextFrameDrop` plus one to the range 1 to 2.
- `engineReboot__Fv` quiets sound, frees the network, removes the vblank handler, ends pad, and calls `LoadExecPS2` with the executable's own disc path, then spins. The host check leaves the spin through a `longjmp` from the mocked `LoadExecPS2`.
- `gameCheckNoSaveZone__Fv` reads `nmPlayers` after `objectIterateRunLists` returns, and `gameLineClear__Fv` rereads `gameLineCount` after each destructor call; the host checks pin both.
- `gameDeathTimerSingle` is indexed by two times a player index with halfword loads, so it is typed as four halfwords. Authored code in `game-state-clear` and elsewhere may treat it as eight bytes; the object is the same 8 bytes.

## Inferred

- Data element widths of `fadeIconY` and `fadeTimer` (28 words) follow the byte size and the authored player-init indexing; no direct access in the image was inspected.
- `0x20000000` in `engineLoadEnvTex__FP8_texture` is taken to be the uncached alias, as in the other engine units.
- `gameLineDebugDraw__Fv` is an empty hook; the image body is only a return.

## Unknown

- What `compositeAlpha`, `engineScissory1/2`, `engineYOffset`, `engineScreenSlide`, `fadeTimer`, `fadeIconY`, `flaredIn`, `flaredOut`, `gameAutoMapMode`, `gameCreatureThinkSpinner`, `gameDeathTimer` and the death-screen values mean beyond their use in the code read.
- Whether `gameDeathTimer` is signed (the image uses both a signed and an unsigned halfword load; the file value is 0xffff).
- The second object named `firstTime` at 0x00483e40 (one byte, file value 1, used by `msg_run__9WaveMaker`) is a different symbol from the one defined here (0x00486d88, used by player selection). Both have the plain symbol name `firstTime` in the image, so a flat link cannot hold both; this package defines only the 0x00486d88 one, which is the one the authored `session-roster-player-selection-start` imports. The other one needs a different binding when `msg_run__9WaveMaker` is authored.
- The type of `levelName` beyond the two text fields at offsets 81 and 161 used by `gameGetFullLevelName__FPc`; the layout of the 80-byte-spaced fields is not established.
- No runtime execution of any of this on an EE or in the game, and no comparison of generated and original instruction behavior (no R5900 interpreter comparison was run for this package).

## Verification run

- Each of the 31 sources compiled with the reviewed toolchain and `authored_cpp` flags; sizes and symbol types of all 20 data objects (`B` for zero values, `D` for 447, 1 and -1) match the file values and sizes.
- Each `host_check.cpp` compiled with `c++ -std=c++17 -Wall` and exited 0. Mutation spot checks (changed clamp bound, comparison direction, destructor flag, arguments of the reboot and death-start calls, field offsets 1328 and 161, shift amount, loop count) each made a numbered check fail.
- A private `ld -m elf32lr5900 -r --warn-common` link of the 31 objects (outside git) defined exactly the 31 names with no COMMON symbols and left the 42 imports listed below undefined. The full `tools/build_partial.py` build was not run: it needs the shared snapshot, which this package must not edit.
- `python3 -m unittest discover -s tools -p 'test_*.py'` results are recorded in the last section.
