# w9-startup-crt-d

Startup and runtime support (d). Sources are under `experimental/sources/w9-startup-crt-d-*`. Each unit compiled alone with the plan's `authored_cpp` flags; host checks (`host_test.cpp`) include host headers and stay out of the EE plan. Addresses are from the private executable whose SHA-256 is the snapshot `target_sha256`. Compiled sizes are `st_size` from the EE compile, not original-byte matches. Nothing was executed on the EE or in game.

## Per-function notes

- `free` (`0x003015a0`, 72 bytes; compiled 64). Observed: lock service, `_free_r` (`0x00300608`) with the pointer re-read, unlock service as a tail call; each `_impure_ptr` read is a fresh load. Callee for `_free_r` is the authored `norrath_player_free_reentrant`. Host check covers order, re-reads and the null pointer reaching `_free_r`.
- `memalign` (`0x00301318`, 100 bytes; compiled 88). Observed: lock, `_memalign_r` (`0x00301380`) with the pointer re-read, then (alignment, size), unlock; returns the `_memalign_r` result. `_memalign_r` is not authored and is a newly opened import.
- `memmove` (`0x003020ac`, 260 bytes; compiled 132). Observed: backward byte copy only when source < destination < source + count (unsigned), otherwise forward; returns the destination. The original's quadword and doubleword fast paths are not reproduced; only byte results are. Host check sweeps all overlap offsets and counts 0..40 against a temp-buffer model.
- `blockFree__FPv` (`0x001447d8`, 84 bytes; compiled 128). Observed: the row is the last one whose start word (offset 8 of the 16-byte row, tested from row 1) is at or below the pointer; the object is pushed onto the list head at row offset 12. That is the existing `norrath_block_free`, so the original name is added as a second global symbol on the same extent (same method as `memAlloc__FiPc`). This edits `experimental/sources/block-allocator-lifecycle-build/block_free.cpp`: its plan file hash must be regenerated. `check_same_extent` against the EE object reports one shared extent of 128 bytes.
- `amx_FindPublic` (`0x00135bb8`, 268 bytes; compiled 268). Observed: binary search over the header's public records (count: signed halfword at header+32; record table offset: word at header+36; 24-byte records, name from +4), strcpy to a 32-byte local then strcmp against the wanted name; found stores the index and returns 0, not found stores `0x7fffffff` and returns 19. Header and count are re-read each iteration. Host check compares against a linear model over empty, one, two, 37 and 38-entry tables, with hits and misses. Unknown: whether 19 has a name, and the rest of the machine object. Opens `strcpy`, `strcmp` (already provided by other packages).
- `kputchar` (`0x002d6778`, 60 bytes, local symbol; compiled 36). Observed: poll the word at `0x1000f130` until bit `0x8000` is clear (fresh read each pass), store the low byte at `0x1000f180`, return the argument. Inferred (not shown by the code): a serial transmit status/data pair, since `serialPutchar` feeds it. Host check scripts the status register and data register through two macros. The original body has padding between the poll and the store that the compiled body lacks.
- `kputs` (`0x002dfa68`, 36 bytes; compiled 36). Observed: one-word local holding the text pointer, `Deci2Call(16, &local)`; the result register is untouched after the call, so the `Deci2Call` result is what returns (callers ignore it). Unknown: what service 16 does. Opens `Deci2Call`.
- `new_iob` (`0x002d89f8`, 136 bytes, local; compiled 160). Observed: `_sceFsIobSemaMK`, `WaitSema(_fs_iob_semid)`, first slot of the thirty-two 16-byte `_iob` slots with a zero word at +4 gets `0x10000000` there, `SignalSema` (id re-read), return the slot, or 0 with none free. Unknown: meaning of `0x10000000`; what `_sceFsIobSemaMK` does. Opens `_sceFsIobSemaMK` (local routine at `0x002d8998`, 92 bytes) and reuses `_iob`, `_fs_iob_semid` from the libfs-state unit.
- `get_iob` (`0x002d8a80`, 108 bytes, local; compiled 128). Observed: same prologue; an index of 32 or more (unsigned) returns 0, otherwise `_iob + index * 16`; semaphore signalled either way. Slot contents are not examined.
- `gsm_create` (`0x002eb790`, 76 bytes; compiled 68). Observed: `__wrap_malloc(2568)`; null returns null; otherwise `memset(p, 0, 2568)`, the 64-bit word at +2472 set to 40, return the block. Inferred only: this looks like the public GSM 06.10 codec state; the image has no field names. Host check verifies every byte of the cleared object and that nothing is written past it.
- `gsm_option` (`0x002edab8`, 44 bytes; compiled 44). Observed: only option 3 acts, anything else returns -1 and touches nothing; option 3 returns the low 32 bits of the 64-bit word at +2464 and, when the pointer is non-null, stores the pointed-at int sign-extended into that word. Inferred only: matches the public library's option of that number.
- `mceGetInfoApdx` (`0x002e1668`, 88 bytes, local; compiled 88). Observed: completion function of `sceMcGetInfo`; reads its argument through the uncached alias (OR `0x20000000`) and copies word 0, word 1 and word 36 to the ints whose addresses are in the three pointer words at `0x008e6b68`, `0x008e6b6c`, `0x008e6b70`, each only if non-null and re-read per test; then tail-calls `iSignalSema` with the word at `0x00446078` (the authored `semaid_timerfunc`; why this completion signals that word is unknown). Opens `iSignalSema`. The pointer views are declared as `int*` here and as arrays in `w8-startup-sce-d-mc-get-info`; same storage, same symbol. Host check sweeps all eight null/non-null combinations.
- `isceSifSendCmd` (`0x002d76d0`, 60 bytes; compiled 32). Observed: forwards to `_sceSifSendCmd` (`0x002d7558`) with the six arguments moved up one place and the constant 1 inserted second; result unchanged. The compiled body tail-calls where the original makes a normal call; results are equal. Unknown: what the arguments and the constant mean. Opens `_sceSifSendCmd`, which the crt-c package also lists.
- `iWakeupThread` (`0x002d5f90`, 148 bytes; compiled 156). Observed: system call number -47 returns the current thread id; if it differs from the argument the call is `_iWakeupThread(thread)`; if equal and the id is below 256 and `topId` (`0x00444958`) is nonzero, the cursor word at `topArg+4` (`topArg` = `0x008de0c8`) is masked with 511 to an index, stored back as index + 1, the pair `{0, id}` is written at `topArg + 8 + 2*index`, `iSignalSema(topSema)` is called (`topSema` = `0x008de0c0`), and the id returns; otherwise -1. The cursor therefore wraps to 1, not 0. The system call is a single inline-asm helper, replaceable by a macro for the host check, which compares 1100 queued wakes against an independent ring model. Opens `_iWakeupThread`, `iSignalSema`; uses the names `topId`, `topSema`, `topArg` from the kernel-patches package. Unknown: what system call -47 itself does beyond returning that id.
- `iSetTimerAlarm` (`0x002df3e8`, 240 bytes; compiled 276). Observed: zero callback returns `0x80000016`; empty free list (`g_pFreeAlarm`, `0x008e4540`) returns `0x80008005`; a negative `iAllocTimerCounter` result puts the record back (first word = old head, +4 cleared) and is returned; otherwise the record gets callback at +8, parameter at +12, counter at +4, `iSetTimerHandler(id, time, AlarmHandler, record)` and `iStartTimerCounter(id)` are called, and `(record << 4) | (id & 0xfe) | 1` returns. Host check covers each exit and the free-list state. Opens `iAllocTimerCounter`, `iSetTimerHandler`, `iStartTimerCounter`, `AlarmHandler` (a local routine at `0x002df258`, 92 bytes). `g_pFreeAlarm` is declared as a record pointer here and as `unsigned` in kernel-patches; same word. Unknown: units of the time value; the three timer calls' bodies.
- `lgAudClose` (`0x002ea380`, 196 bytes; compiled 192). Observed: semaphore word `0x00447f7c` equal to -1 returns `0x8000000a`; otherwise wait, handle to word 3 of the aligned block (`0x00447f74`), `sceSifCallRpc(client 0x008ea780, 3, 0, block, 32, block, 32, 0, 0)`; nonzero result prints the text "lgAudClose: rpc call failed" with a newline, signals and returns `0x80000000`; zero result reads block word 0, signals, and returns that word. Reuses the `norrath_lgaud_*` names from `w8-startup-sce-b-lg-aud-init`. Host check scripts every callee and verifies the status word is read before the signal. Opens `printf`, `sceSifCallRpc`, `WaitSema`, `SignalSema` (all already imports).
- `lgKbMInit` (`0x002e6ed0`, 412 bytes; compiled 416). Observed sequence is in the source header: already-initialised flag at `GLibData`+52 (prints a refusal text, returns `0x80000000`); version banner (1, 6, 1, "1.06.001", priority); limits at +64/+68 replaced by 4 when 5 or more; constants 1 at +96, 100 (64-bit) at +112, 500 at +120, 75 at +132; `qsort_translate_table(KbdMapTable, 0, 74)` with the table address stored at +124; `CreateSema` on a six-word block with only words 1 and 2 written (both 1), result at +44, -1 prints a text and loops forever; `connect_to_iop_server`; a non-null fourth argument stored at +128 or else `init_ee_timer` and the address of `get_time`; `CreateReaderThread(priority)`; flag +52 = 1; return 0. The original's null test of `KbdMapTable` is not reproduced (an object address is never null). Host check covers all paths including a long jump out of the endless stop loop. Opens `GLibData` (defined by the keyboard package at `0x008ebdd8`), `KbdMapTable` (`0x00447c60`, 750 bytes, not authored anywhere I found), `qsort_translate_table`, `connect_to_iop_server`, `init_ee_timer`, `get_time`, `CreateReaderThread`, `CreateSema`, `printf`. Unknown: what the two limits and the +112/+120 constants mean.
- `initEzNetCnf` (`0x010becd0`, 200 bytes, overlay range; compiled 256). Observed: same shape as the authored `initEzNetCtl`, with module name "eznetcnf", server `0x75499128`, client at `0x011e8380` (64 bytes), flag at `0x01192c68` set to 1 once client word 9 is nonzero; lookup and bind failures print and continue; countdown from `0x10000` to -1 between binds. Caveat: the flag is the word `exitEzNetCnf` (vi-launcher package) clears; both units hold file-local copies, so storage is not yet shared. Host check covers the clean, missing-module and slow-server cases.
- `fptodp` (`0x002fb320`, 60 bytes; compiled 60). Observed: stores the float, `__unpack_f` (`0x002ff4a8`) into a 16-byte record (class, sign, power, 32-bit fraction at +12), then `__make_dp` (`0x002fbbf0`) with class, sign, power and the fraction shifted left 30 as a 64-bit value; the 64-bit result returns unchanged. `math-entity-fptodp` authors the same path flattened as `norrath_entity_fptodp`; this unit keeps the call structure and opens `__unpack_f` and `__make_dp`. Host check scripts both callees and verifies the arguments and the 64-bit shift.
- `dptofp` (`0x002fbc20`, 84 bytes; compiled 84). Observed: the 64-bit argument is stored, `__unpack_d` (`0x002ff610`) fills a 32-byte record (class +0, sign +4, power +8, 64-bit fraction +16), then `__make_fp` (`0x002ff508`) gets class, sign, power and the fraction shifted right 30 with bit 0 set if any of the fraction's low 30 bits are set; its float result returns unchanged. Host check varies the fraction across the sticky-bit boundary (bit 29 sets it, bit 30 does not). Opens `__unpack_d`, `__make_fp`. Unknown: those callees' bodies.
- `dpcmp` (`0x002fba48`, 76 bytes; compiled 64). Observed: both 64-bit arguments are unpacked into two separate 32-byte records, then `__fpcmp_parts_d` (`0x002ff6d0`) on the pair; its int result returns unchanged. Opens `__fpcmp_parts_d`. Unknown: result value meanings.
- `dpadd` (`0x002fb5c0`, 88 bytes; compiled 76). Observed: both 64-bit arguments are unpacked with `__unpack_d` into two 32-byte records; `_fpadd_parts` (`0x002fb360`, a local routine) takes them plus a third 32-byte scratch record; the returned record pointer goes to `__pack_d` (`0x002ff538`) and its 64-bit result returns unchanged. Host check scripts the three callees and checks operand order, distinct records and the sign words. Opens `_fpadd_parts`, `__pack_d`.
- `dpsub` (`0x002fb618`, 100 bytes; compiled 88). Observed: same as `dpadd`, except the sign word of the second unpacked record is exclusive-ORed with 1 before `_fpadd_parts`. Same host check with the flipped sign expected on the second record.

## Summary

Imports closed (22 functions, one unit each): amx_FindPublic, dpadd, dpcmp, dpsub, dptofp, fptodp, free, get_iob, gsm_create, gsm_option, iSetTimerAlarm, iWakeupThread, initEzNetCnf, isceSifSendCmd, kputchar, kputs, lgAudClose, lgKbMInit, mceGetInfoApdx, memalign, memmove, new_iob. `blockFree__FPv` is closed by publishing the original name on the existing `norrath_block_free` extent (edit in block-allocator-lifecycle-build; its plan file hash needs regenerating).

Already defined by authored units elsewhere in the tree, so nothing was authored here: memAlloc__FiPc, memFree__FPv, memRealloc__FPvi, memCheckHeapReal__FPCci (w8-object-list-math-* units, already in the plan); isin__Fi (w8-object-list-math-isin, in the plan; runtime-tables also has one). The views norrath_archive_vblank_{count,field,semaphore}_view (sony-cd-vblank-views) and norrath_libmtap_*_view, norrath_libmtap_rpc_buffer_view, norrath_libpad_dma_info_view (simloop-services-pad-mtap-state) exist as sources but are not in the plan at this base; those plan entries belong to their owners.
