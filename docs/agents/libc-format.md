# libc-format

Runtime formatting and reentrant I/O for the partial build. Each translation unit below was compiled with the reviewed `authored_cpp` flags. Host checks live beside the sources and must stay out of the EE plan: they include the host C library and stub callees. No EE object from this package was linked into `experimental/build-plan.json` or executed on the target.

Comparisons below are against the local executable whose SHA-256 is the snapshot `target_sha256`. Sizes named "compiled" are `st_size` from that EE compile. They are not original-byte matches.

## Observed

- `norrath_factory_memchr` is `memchr` at `0x0030b314`, 224 bytes. It masks the needle to eight bits and treats the count as unsigned. A 16-byte-aligned quadword scan precedes the byte loop. The authored function is the byte result only. Compiled body: 64 bytes. Host check: 108161 comparisons with the host `memchr`.
- `norrath_factory_mbtowc_reentrant` is `_mbtowc_r` at `0x0030b2e0`, 52 bytes. The reentrancy pointer and shift state are unused. A null input returns 0. A zero maximum returns -1 and stores nothing. Any other input stores the first byte as a zero-extended 32-bit word, including when the wide-character pointer is null, and returns 0 for a zero byte and 1 otherwise. Compiled body: 80 bytes.
- `norrath_factory_localeconv` is `localeconv` at `0x0030af10`, 28 bytes, which loads `_impure_ptr` and tails into `_localeconv_r` at `0x0030aed8`. That callee ignores its argument and returns `lconv` at `0x0047f438` (48 bytes): ten pointers, then eight `127` bytes. `decimal_point` aims at `"."`; the other nine strings aim at one empty string. Compiled body: 28 bytes. The impure load is kept live and does not select the object.
- `norrath_factory_close_reentrant`, `norrath_factory_read_reentrant`, `norrath_factory_write_reentrant`, and `norrath_factory_seek_reentrant` are `_close_r` (`0x003094d0`), `_read_r`, `_write_r`, and `_lseek_r`. Each clears the `errno` word, calls the raw function, and writes that word to the reentrancy object only when the result is -1 and the word is nonzero. The seek offset is one 64-bit value, compared in full to -1. Compiled bodies: close 164, read 172, write 172, seek 172.
- `norrath_factory_stream_write_setup` is `__swsetup` at `0x003093c0`, 268 bytes. A zero owner at file+84 is replaced with the impure pointer. A zero word at reentrancy+56 calls `norrath_factory_streams_init`. Without the write bit (`8`) and without read/write (`0x10`) it returns -1. A read-to-write switch frees a heap ungetc buffer unless it is null or the tiny buffer at file+64, then clears bits `0x24`, zeroes the read count, and sets the cursor to the buffer base. The write bit is then set. A null base calls `norrath_player_stream_make_buffer`. Line-buffered streams store a zero write count and a line-buffer size of `0 - size`. Unbuffered streams store a zero write count. Other streams store the buffer size. Compiled body: 564 bytes.
- `norrath_format_string` is `sprintf` at `0x00303eb8`, 144 bytes, the callee of `MC_LoadLevelEntities`. It builds an 88-byte stream with flags `0x208`, write count and buffer size `0x7fffffff`, base and cursor at the destination, and owner from the impure pointer, then calls `norrath_factory_vfprintf` and writes a trailing NUL at the cursor that call leaves behind. Compiled body: 172 bytes. This is a second definition of that setup, beside the existing `norrath_factory_sprintf`.
- `norrath_sce_printf` is `scePrintf` at `0x002d70d0`, 96 bytes. It saves `_putchar` (`0x00444960`, initially `serialPutchar` at `0x002d6868`), installs `deci2Putchar` (`0x002d67b8`), calls `_printf` (`0x002d6aa0`, 1524 bytes), restores the hook, and returns that result. Compiled body: 104 bytes. The same bytes are also exported as `scePrintf`; the EE object has one body and both names. This unit also defines `_putchar`, initialized to `serialPutchar`.
- `sscanf` at `0x00303f50`, 168 bytes, is not one of the `norrath_*` bodies from this package. It stores a read-only string stream (flags 4, cursor and base at the input, size and read count from `strlen` at `0x00304cfc`, owner from `_impure_ptr`, zero at +48 and +68) and the 8-byte `eofread` at `0x00303f48`, then calls `__svfscanf` at `0x003083e8`. The authored names of those callees are `norrath_factory_strlen`, `norrath_player_string_eof_read`, `norrath_factory_impure_pointer_word`, and `norrath_player_stream_scan`. `norrath_player_sscanf` is that same original function under another name; this unit is the `sscanf` symbol `main`/`launchSRS` import. Compiled body: 344 bytes. The original also spills `f12`–`f19` under the integer argument cursor. This uses the compiler varargs cursor.
- `strcmp` at `0x003044fc`, 324 bytes, is not an existing authored function. Aligned inputs use 16-byte and 8-byte equality scans, then an unsigned byte subtraction. The authored function is that byte result. Compiled body: 40 bytes. `main` compares `--net` and `--mainmenu`.
- `memcpy` at `0x00301ffc`, 176 bytes, is already defined under that name on `origin/agents/gameobject-base` (`experimental/sources/gameobject-base-memcpy/memcpy.cpp`). This package does not define it again.
- `norrath_player_syscall_errno_word` is `errno` at `0x00486df0`, 4 zero bytes in small BSS. It is separate from the impure object. No function is emitted.
- `norrath_factory_impure_pointer_word` is `_impure_ptr` at `0x00448480`, initially `0x00448190`. `impure_data` there is 752 bytes. Nonzero words: +4/+8/+12 point at the embedded streams at +484/+572/+660; +52 points at the `"C"` string; +168 is the 64-bit seed 1. The three 88-byte stream bodies are zero. No function is emitted. On the EE object the image is local and the public symbol is the 4-byte pointer.
- `norrath_factory_ctype_minimum_view` is the 384-byte window from `0x0047e171` through the last byte of `_ctype_` (`0x0047e1f0`, 257 bytes). Callers index `view[character + 128]`, which is `_ctype_ + 1 + character`. The 384 bytes match the image, including the 127 preceding bytes a signed index of -128 can read. No function is emitted.
- `norrath_factory_mb_cur_max_word` is `__mb_cur_max` at `0x004488e8`, little-endian 1. No function is emitted.
- Formatter views, used as C strings or as exact 16-byte pads by the existing core formatter, match the cluster at `0x0047ed60`: 16 spaces, 16 ASCII `0` bytes, `"Inf"`, `"NaN"`, `"0123456789abcdef"`, `"(null)"`, `"0123456789ABCDEF"`, `"0"`, `"."`. No function is emitted. `norrath_formatter_bad_base_view` is not an unresolved import; the string is present in the image and this package does not define it.
- Dtoa views match `0x0047f3e0`: `"Infinity"` (byte 3 is nonzero, so the existing end rule is start+8), `"NaN"` (byte 3 is zero, so start+3), and `"0"` (end is address+1). The three little-endian doubles at `0x0047f400` are `0x1.287a7636f4360p-2`, `0x1.68a288b60c8b2p-3`, and `0x1.34413509f79fbp-2`. No function is emitted.

## Inferred

- File offsets follow the newlib `FILE` already used by the authored stream code: cursor +0, read count +4, write count +8, flags +12, descriptor +14, base +16, size +20, line-buffer size +24, ungetc base +48, tiny ungetc buffer +64, owner +84.
- Flag bits used by write setup are line `1`, unbuffered `2`, read `4`, write `8`, read/write `0x10`, and end-of-file `0x20`.
- The raw names `close`, `read`, `write`, and `lseek` are the observed callee symbols, not new `norrath_` names.

## Unknown

- The memchr quadword scan is not reproduced. The byte function matches ordinary memory results; it does not match the original access width or the 224-byte body.
- `_printf` is not reconstructed. `norrath_sce_printf` only swaps the hook.
- `read` at `0x002d5728` accepts descriptor 0 through the tty path and otherwise returns -1. `write` at `0x002d56a8` accepts descriptors 1 and 2 through the tty path and otherwise returns -1. Those paths need `sceTtyInit`, `sceTtyRead`, `sceTtyWrite`, and the tty flag word, which are outside this package.
- `close` at `0x002d57c8` and `lseek` at `0x002d57d8` are eight-byte stubs that return -1 and do not set `errno`. They are left unresolved.
- `sprintf` and `sscanf` spill floating registers below the integer argument cursor. The authored functions use the compiler varargs cursor. Float arguments beyond that cursor are not newly claimed.
- The 16-byte and 8-byte `strcmp` scans are not reproduced. The byte function returns the unsigned difference; it does not match the original access width or the 324-byte body.
- The 127 bytes before `_ctype_` are adjacent image bytes, not a separately named table. Publishing them is required for the caller's `character + 128` index.
